# 音频组件适配说明（补稿，待审）

日期：2026-11-27　你问「有没有考虑到音频组件的适配？」——**原平板稿没覆盖独立播放页**，这轮补上。

## 一、现状实测（未改）

| 视口 | 字幕区宽 | 问题 |
|---|---|---|
| 820×1180 竖屏 | 820px | 字幕拉满宽，右侧无留白；歌词行过长 |
| 1180×820 横屏 | 1100px | 字幕被拉成 1100px 单行，**右侧 2/3 空白**，播放键/进度条挤在底部跨全宽 |

截图：`音频页_竖屏820_现状.png`、`音频页_横屏1180_现状.png`

## 二、补稿方案

| 文件 | 内容 |
|---|---|
| `音频组件稿_竖屏.png` | 播放页竖屏：内容 720px 居中，曲名 → 逐句字幕 → 四操作 → 进度 → 播放三键 → 底导航 |
| `音频组件稿_横屏.png` | 播放页横屏：**左 720 字幕区 + 右辅助列**（封面卡/收藏·缓存·循环·字幕/进度/播放键），控件不跨全宽 |
| `m3e_audio_design.json` | 项目文件留档 |
| `m3e_audio_prompt.txt` | 提示词 3801 字，0 undefined |

核心原则：**字幕行宽始终 ≤720px**，横屏不拉伸、右列承载控件，避免「一行字幕横跨 1100px + 大片空白」。

## 三、与已有音频点的关系

- 盲听/精听/跟读页里的**小播放条**已在四屏稿内（跟读屏有紧凑播放条），不需要另改。
- 本补稿只针对**独立播放页 `#/player`** 和它承载的听单入口。
- 音频单例 `<audio>`、断点续播、字幕逐句高亮逻辑不变，只改布局。
